# 第二阶段验收报告：Agent 群聊与任务协作

> 日期：2026-10-30 · 在第一阶段基础上新增，不修改已有数据表（全部为新增表）

## 1. 已完成功能

| 功能 | 实现方式 | 状态 |
|---|---|---|
| 群聊 | 创建、改名、归档；左侧群列表（未读任务数、最后消息）、中间消息流、右侧任务/成员面板 | ✅ |
| 成员管理 | 添加/移除 Agent、设置角色（分析/执行/审查/汇总）、设置/取消主控 Agent | ✅ |
| @Agent / @全体 | 输入框 `@` 自动补全；后端同时解析文本（支持名称含空格）；被 @ 的必须是群成员 | ✅ |
| 人工指定模式 | 被 @ 成员按角色分阶段：分析 → 执行 → 审查 → 汇总，同阶段并行；或用「分工」面板逐个指定角色（覆盖默认角色） | ✅ |
| 自动协作模式 | 主控 Agent 输出 JSON 计划 → 平台校验（成员存在、依赖存在、无环、≤12 步）→ 生成子任务 → 按依赖 DAG 调度 → 主控最后汇总。未设主控时由平台调度器按成员角色分工（并在群里说明） | ✅ |
| 子任务管理 | 每个步骤 = 一个子任务（独立 AgentRun），共享根任务的 Trace 与工作目录；步骤详情可跳转子任务完整执行事件 | ✅ |
| 任务交接（结构化） | `handoffs` 表：交接 ID、交出/接收 Agent、原因、上下文、已完成、未完成、相关文件、执行结果、交接/接收/完成时间、接收状态（待接收→已接收→已完成/失败）。三种来源：平台（依赖完成时）、Agent 主动（回复末尾 ```handoff``` JSON 块，平台校验目标成员并新建步骤，最多 5 次防循环）、人工改派 | ✅ |
| 执行状态 | 任务：待执行/执行中/等待审批/等待交接/已暂停/完成/失败/取消；步骤：同上 + 跳过；实时推送 | ✅ |
| 暂停 / 恢复 | 暂停后不再启动新步骤；**正在执行的外部 Agent 进程无法冻结，会完成当前步骤**（界面如实提示） | ✅ |
| 终止 | 结束所有运行中的 Agent 进程，未开始步骤标记取消 | ✅ |
| 人工介入 | 补充说明（注入后续所有步骤的提示词）、追加步骤、重试失败步骤（自动重开被跳过的下游）、跳过、改派 | ✅ |
| 审批 | ① 计划审批：群设置「计划需审批」后，主控计划在执行前等待批准，拒绝则任务终止；② 高风险步骤审批：分配给高风险配置 Agent（如开放写文件/命令）的步骤执行前必须由 **管理员** 批准，operator 无权批准 | ✅ |
| 历史聊天记录 | 消息持久化（用户/Agent/系统、计划、交接、审批、结果、人工介入），新任务的提示词会附带群聊近期记录 | ✅ |
| 任务中心 / 工作台 | 只显示根任务，子任务的执行/Token/成本汇总到根任务；任务详情页展示协作过程 | ✅ |

## 3. 本阶段发现并修复的问题
- **SQLite 写锁死锁**：编排器在未提交的事务中再开会话写消息，导致 `database is locked`。改为事务提交后再发布消息（审批通知、重试审计两处）。

## 5. 使用方式
1. **Agent 群聊 → +** 新建群聊，选择成员 Agent，可选主控。
2. 右侧「成员」设置各 Agent 角色、主控、是否需要计划审批。
3. 输入框：**人工指定**——`@Agent` 后描述任务；**自动协作**——直接描述任务，主控拆分；**仅聊天**——只记录。
4. 右侧「协作任务」查看步骤、交接详情、审批（批准/拒绝），暂停/恢复/终止，提交补充说明、追加步骤；点步骤可重试/跳过/改派。
