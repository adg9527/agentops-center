# 01 · 产品需求分析与技术架构设计

> 项目代号：**AgentOps Center**（AI Agent Operations & Evaluation Center）
> 文档日期：2026-10-30 · 适用阶段：全局（第一阶段起生效）

## 1. 需求理解

平台定位不是"聊天网页"或"工作流编辑器"，而是 **Agent 运营与评测中枢**：

| 维度 | 核心诉求 | 设计含义 |
|---|---|---|
| 接入 | 复用已有 Agent（Claude Code / Codex / OpenCode / Gemini CLI / 自研服务） | 平台不"重建"Agent，而是通过 **Adapter** 驱动外部 Agent；能力差异必须显式建模 |
| 协作 | 群聊式多 Agent 协作，人工指派或主控自动拆分 | 聊天消息只是表现层，底层是 **结构化任务 / 子任务 / 交接(Handoff)** 状态机 |
| 观测 | 看到 Agent 实际做了什么 | 统一 **Trace/Span 事件模型**（参考 OpenTelemetry），不采集未公开思维链 |
| 资产 | MCP / Skill / Prompt / Agent 配置统一管理 | 统一 **资产-版本** 模型，版本内容不可变快照 |
| 评测 | 多对象、多评分器、横向/纵向对比 | 评测运行绑定 **具体资产版本 ID**，报告保存快照 |
| 安全 | 不允许默认任意执行命令 | 默认 **只读工具白名单**，高风险操作需审批，密钥加密、脱敏、审计 |

### 1.1 关键约束与真实性原则

1. **能力三态标注**：每个 Adapter 对每项能力声明 `supported / partial / unsupported / unknown`，UI 原样展示，不伪造。
2. **数据真实**：Dashboard/评测图表只从数据库真实记录聚合；尚未实现的模块明确显示"第 N 阶段实现"，不展示假数字。
3. **不碰用户已有环境**：Agent 默认在平台托管的独立工作目录 `data/workspaces/<task_id>` 中运行；不执行 `docker system prune` 等命令。

## 3. 技术选型与调整说明

| 层 | 建议方案 | 实际选型 | 调整原因 |
|---|---|---|---|
| 前端 | React + TS | React 18 + TypeScript + Vite | 一致 |
| UI | 成熟组件库 | Ant Design 5（暗色算法） | 表格/抽屉/表单/时间线组件完整，适合管理控制台 |
| 图表 | ECharts | **Ant Design Charts 2（G2 v5）** | 按用户要求（2026-10-30）替换 ECharts，与 Ant Design 组件体系一致 |
| 后端 | FastAPI | FastAPI + SQLAlchemy 2.0 (async) | 一致 |
| 平台内置智能体 | — | **LangChain 1.x（create_agent）+ langchain-openai / langchain-anthropic** | 按用户要求，用 LangChain 开发后端智能体；回调映射为 Trace 事件 |
| 数据库 | PostgreSQL | **SQLAlchemy 抽象，PostgreSQL / SQLite 双支持**；开发默认 SQLite | Docker Desktop 当前未运行；通过 `DATABASE_URL` 切换到 PostgreSQL（asyncpg），模型不使用方言特有类型 |
| 实时通信 | WebSocket/SSE | WebSocket（`/api/ws`） | 双向，后续群聊需要用户输入推送 |
| 任务队列 | Redis + Celery | **进程内 asyncio 调度器**（第一阶段），预留队列接口 | Celery 官方不支持 Windows（prefork 不可用）；外部 Agent 本身是宿主机子进程，瓶颈在 Agent 而非 Python 计算；任务状态全部持久化在 DB，重启自动恢复/标记中断 |
| Trace | OTel 兼容 | 自有 `trace_events` 表，字段对齐 OTel（trace_id/span_id/parent_span_id），预留 OTLP 导出 | 第一阶段即落库，第三阶段扩展检索与回放 |
| 部署 | Docker Compose | **后端宿主机原生运行**，PostgreSQL/Redis 用 Compose | 关键：Claude Code/OpenCode 等 CLI Agent 安装在宿主机，使用宿主机登录凭据；容器内后端无法驱动宿主机 CLI。第七阶段提供"宿主机 Agent Runner + 容器化 Web/DB"组合方案 |

## 4. 总体架构（模块化单体）

```
┌──────────────────────── Browser (React + AntD + ECharts) ───────────────────────┐
│ 工作台 │ 群聊 │ Agent │ MCP │ Skill │ Prompt │ 任务 │ 监控 │ 评测 │ 报告 │ 版本 │ 设置 │
└───────────────▲ REST (JSON) ─────────────────────▲ WebSocket (事件推送) ───────────┘
                │                                    │
┌───────────────┴────────────── FastAPI 模块化单体 ───┴────────────────────────────┐
│  api/        认证 · RBAC 依赖 · 各模块路由                                         │
│  services/   TaskRunner(调度/并发/超时/重试) · EventBus(发布订阅) · Audit · Trace  │
│  adapters/   AgentAdapter 抽象 ─┬─ ClaudeCodeAdapter (CLI stream-json)           │
│                                ├─ OpenCodeAdapter   (CLI json events)           │
│                                ├─ LangChainAdapter  (平台内置, create_agent)     │
│                                ├─ CodexAdapter      (CLI exec --json, 未验证)    │
│                                └─ HttpAgentAdapter  (通用 HTTP)                  │
│  (后续) collab/ 群聊+编排  assets/ 资产版本  eval/ 评测+评分器  reports/ 报告      │
│  security/   Argon2 口令 · JWT · Fernet 密钥加密 · 脱敏                           │
└───────────────┬──────────────────────────────────┬───────────────────────────────┘
                │ SQLAlchemy                        │ 子进程 / HTTP
        ┌───────┴────────┐                 ┌───────┴─────────────────────┐
        │ SQLite / PG    │                 │ 外部 Agent（宿主机 CLI/服务）  │
        └────────────────┘                 └──────────────────────────────┘
```

**模块边界原则**：每个业务模块（agents / tasks / collab / assets / eval / reports）拥有自己的 models、schemas、service、router；跨模块只通过 service 接口调用，以便日后拆分。

## 5. Agent Adapter 设计要点

```python
class AgentAdapter(ABC):
    type: str                      # "claude_code" / "opencode" / "codex" / "http"
    transport: str                 # cli / http / mcp / sdk / webhook / a2a
    verified: bool                 # 是否在本环境实测验证
    config_fields: list[ConfigField]   # 驱动前端动态表单
    static_capabilities: dict[str, CapabilityLevel]

    async def check_connection(cfg) -> ConnectionResult      # 连接检测
    async def detect_capabilities(cfg) -> dict               # 能力检测（可实测的部分）
    async def run(req, emit, cancel) -> RunResult             # 任务发送 + 事件上报 + 结果获取
```

- 任务取消通过 `cancel` 事件实现，CLI 类 Adapter 以 `taskkill /T` 结束进程树。
- 状态查询：平台侧持久化运行状态，Adapter 只负责事件流；对支持会话的 Agent 记录 `external_session_id`。
- Adapter 把平台原生事件 **归一化** 为：`agent.message / model.call / tool.call / tool.result / permission.denied / session.started`，由 TraceService 转换为 Span 事件。

## 6. 安全设计（第一阶段已落地部分标 ✅）

- ✅ 用户认证：Argon2 哈希 + JWT；首次启动在网页上创建管理员（无默认口令）。
- ✅ RBAC：`admin / operator / viewer`。
- ✅ 密钥加密：Agent 的 API Key/Token 等密文字段以 Fernet 加密入库，API 永不回传明文（只返回 `******` 与是否已设置）。
- ✅ 日志脱敏：事件摘要写库前按规则 + 已知密钥值脱敏。
- ✅ 审计日志：登录、Agent 增删改启停、连接测试、任务创建/取消。
- ✅ 最小权限：Claude Code 默认 `--tools Read Glob Grep`、隔离用户级设置与 MCP；OpenCode 默认 `edit/bash/webfetch = deny`。
- ✅ 执行超时 / 最大重试 / 单 Agent 并发上限 / 全局并发上限。
- ✅ 工作目录隔离：每个任务独立目录。
- ⏳ 高风险操作审批（第二阶段，配合"等待审批"状态）、MCP 调用权限门控（第四阶段，通过平台生成的 `--mcp-config` 实现真正的启停）。
