# 02 · 功能模块拆分、数据库设计与核心数据流

## 1. 模块拆分

| 模块 | 后端包 | 主要实体 | 阶段 |
|---|---|---|---|
| 认证与权限 | `api/auth` `security` | User | 1（RBAC 细化在 7） |
| 项目 | `api/projects` | Project | 1（基础）/ 7 |
| Agent 接入 | `adapters/` `api/agents` | Agent, AgentVersion* | 1 |
| 任务 | `services/task_runner` `api/tasks` | Task, AgentRun | 1 |
| Trace | `services/trace` `api/events` | TraceEvent | 1（落库）/ 3（检索/回放） |
| 群聊协作 | `collab/` | Conversation, ConversationMember, Message, Handoff, Approval | 2 |
| 资产 | `assets/` | Asset, AssetVersion（MCP/Skill/Prompt/AgentConfig 统一） | 4 |
| 评测 | `eval/` | Dataset, DatasetVersion, TestCase, Scorer, EvalJob, EvalCaseResult | 5 |
| 报告 | `reports/` | Report, ReportVersion（含快照 JSON） | 6 |
| 审计 | `services/audit` | AuditLog | 1 |

## 2. 数据模型

### 2.1 第一阶段已实现

```
users(id, username UNIQUE, password_hash, role[admin|operator|viewer], is_active, created_at)

projects(id, name UNIQUE, description, created_at)

agents(
  id, project_id→projects, name, adapter_type, platform, transport,
  description, role, capability_tags JSON,
  config JSON,                 -- 非敏感连接/启动配置
  secret_config TEXT,          -- Fernet 加密的 JSON（API Key 等），永不明文返回
  model,                       -- 用户配置的模型（可空 = Agent 默认）
  detected JSON,               -- 最近一次连接/能力检测结果（版本、模型列表、工具…）
  enabled BOOL, health[online|offline|unknown], last_seen_at, last_check_at,
  max_concurrency, timeout_sec, max_retries, config_version INT,
  created_at, updated_at)

tasks(
  id, project_id, title, prompt, mode[direct|...], status, parent_task_id→tasks,
  conversation_id (第二阶段外键), trace_id, workspace_dir,
  created_by→users, created_at, started_at, finished_at, error)
  status ∈ pending | running | waiting_approval | waiting_handoff | paused
           | completed | failed | cancelled

agent_runs(
  id, task_id→tasks, agent_id→agents, agent_config_version, attempt,
  status[pending|running|completed|failed|cancelled|timeout],
  span_id, external_session_id, output_text, error,
  input_tokens, output_tokens, cost_usd, model_used,
  started_at, finished_at, duration_ms)

trace_events(
  id, event_id UNIQUE, trace_id, span_id, parent_span_id,
  task_id, run_id, agent_id, event_type, name, timestamp,
  status, duration_ms, input_summary, output_summary, metadata JSON)
  INDEX(trace_id), INDEX(task_id), INDEX(agent_id, timestamp), INDEX(event_type)

audit_logs(id, user_id, username, action, target_type, target_id, detail JSON, ip, created_at)
```

### 2.2 后续阶段设计（预定义，届时以迁移脚本新增）

```
-- 第二阶段：协作
conversations(id, project_id, name, coordinator_agent_id, created_by, created_at)
conversation_members(conversation_id, agent_id, role[executor|analyst|reviewer|summarizer|coordinator])
messages(id, conversation_id, sender_type[user|agent|system], sender_id, content,
         mentions JSON, task_id, created_at)
handoffs(id, task_id, from_agent_id, to_agent_id, reason, context JSON,
         done_work, remaining_work, files JSON, result, status[proposed|accepted|rejected|completed],
         created_at, accepted_at)
approvals(id, task_id, run_id, kind, request JSON, status, decided_by, decided_at)

-- 第四阶段：统一资产版本
assets(id, project_id, kind[mcp|skill|prompt|agent_config], name, description,
       enabled, current_version_id, created_at, updated_at)
asset_versions(id, asset_id, version_no, content_snapshot JSON, files_blob_ref,
               change_note, created_by, created_at, publish_status[draft|published|archived],
               enabled, content_hash)            -- 版本行不可变，只追加

-- 第五阶段：评测
datasets / dataset_versions / test_cases(id, dataset_version_id, category, input, expected JSON, scorer_cfg)
eval_jobs(id, name, target_kind, target_refs JSON[{agent_id, asset_version_ids…}],
          dataset_version_id, scorers JSON, repeats, concurrency, timeout, retry, status)
eval_case_results(id, eval_job_id, test_case_id, agent_run_id, scores JSON, passed, error_type)

-- 第六阶段：报告
reports(id, eval_job_id, project_id, title, snapshot JSON, version_no, archived, created_at)
```

**可追溯性约束**：评测与报告只引用 `asset_versions.id` / `dataset_versions.id`（不可变），报告生成时把被测对象版本内容、评分规则、统计结果整体写入 `snapshot`，后续资产修改不影响历史报告。

## 3. 核心数据流（第一阶段）

```
用户 ──POST /api/tasks──▶ TaskService.create
                         ├─ 写 tasks(status=pending)、agent_runs(pending) 每个目标 Agent 一条
                         ├─ 审计日志
                         └─ TaskRunner.submit(task_id)
                                │ asyncio 任务；全局并发信号量 + 每 Agent 信号量
                                ▼
                     Adapter.run(req, emit, cancel)
                         │ 子进程 stdout 逐行 JSON ──▶ 归一化 AdapterEvent
                         ▼
                     TraceService.record(event) ──▶ trace_events 落库（脱敏）
                         │                         └▶ EventBus.publish ──▶ WebSocket ──▶ 前端时间线
                         ▼
                     RunResult(输出、tokens、cost、session)
                         └─ 更新 agent_runs / tasks 状态（失败按 max_retries 重试；超时/取消杀进程树）
```

### 3.1 Trace 串联规则

- 一个 Task = 一个 `trace_id`。
- 每个 AgentRun = 一个 Span（`span_id`），父 Span 为任务根 Span。
- 每次工具调用 = 子 Span（父为 AgentRun Span），`tool.call` 与 `tool.result` 共享 span_id。
- 第二阶段的子任务/交接沿用父任务 `trace_id`，从而多个 Agent 的执行记录自然串联。
